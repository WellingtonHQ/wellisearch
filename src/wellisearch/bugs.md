## ⚠️ Three quirks worth fixing (none are blockers)

1. **`search_web` results show `Title: <url>`** — the first test returned `Title: https://www.databricks.com/blog/what-is-pgvector` instead of a real page title. The bulk fetch *does* have a `Title:` field (e.g. "PostgreSQL 18.6 Documentation"), so the search pipeline is falling back to the URL when it has no title. Worth checking whether provider results (Tavily returns titles) and/or stored `pages.title` are being threaded into the `results` block.
2. **Default strategy mismatch** — my single `fetch_page` call (no strategy specified) was truncated with `strategy=head`, but the plan default is `FETCH_DEFAULT_STRATEGY=smart` [1]. Either the server default is `head`, or `fetch_page` is intentionally `head`-based — worth a one-line check in the config to make the two consistent.
3. **Title extraction picks nav links on some pages** — the Databricks page came back with `Title: [Skip to main content](...)` (a skip-link anchor, not the article title). A small "prefer `<h1>`/`<title>` over first link" heuristic in the crawler would fix that class of issue.
4. `search_web` via the owui call should return pure markdown the same way as `fetch_page` does. Right now it is returning a JSON object which does not show well on the owui interface.

**Bottom line:** the whole loop — `search_web` → local index hit → `fetch_page`/`fetch_pages` reads with budgeted truncation → provider failover on misses → background indexing — is all functional.
